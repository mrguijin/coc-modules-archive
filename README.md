## 一、它能帮你做什么

跑团圈子里的现状通常是：模组信息散在群公告和在线文档里，带团记录靠脑子记，角色卡是 Excel 传来传去，KP 审卡靠肉眼逐项核算。

这个项目把这四件事变成了一个有权限、有留痕、有规则校验的站点：

| 痛点 | 这个项目里的答案 |
| --- | --- |
| 模组信息散落、找不到"适合几人的 1920s 短团" | 结构化档案 + 地区/人数/时长/时代筛选 + 合集归类 + 置顶 |
| 带团履历说不清（带过多少场、多少小时） | 守秘人控制台逐场记录，自动统计并导出长图 |
| 车卡算派生值算到吐，还容易算错 | 掷骰、年龄补正、HP/MP/理智/移动力/伤害加值全自动 |
| 玩家点数超支、混点、信用评级越界 | 前端实时提示 + 服务端权威重算，改不了数据 |
| KP 审卡逐项核对 | 9 条可选审卡规则自动判定 + 批量审卡 + 批复留痕 |
| 角色卡打印要另找工具 | 浏览器原生 A4 双页版面，直接打印或另存 PDF |

## 二、功能与权限

三种身份，能力逐级叠加：

| 能力 | 访客 | 调查员 | 守秘人（KP） |
| --- | :-: | :-: | :-: |
| 浏览/检索模组档案、复制简介 | ✅ | ✅ | ✅ |
| 免登录车卡 + A4 打印 / 另存 PDF | ✅ | ✅ | ✅ |
| 标记"已调查"、个人中心、结业证书 | — | ✅ | ✅ |
| 我的角色卡（增删改、复制、打印） | — | ✅ | ✅ |
| 角色卡关联跑团模组（写入「经历」） | — | ✅ | ✅ |
| 提交 KP 审核 / 查看批复 | — | ✅ | ✅ |
| 发布 / 编辑 / 置顶 / 删除模组 | — | — | ✅ |
| 守秘人控制台（带团记录、盘点、长图） | — | — | ✅ |
| 账号发放 / 重置口令 / 授予头衔 / 删除 | — | — | ✅ |
| 全站角色卡管理、代建代改、批量打印 | — | — | ✅ |
| 审卡中心（规则审卡、批量通过/驳回、职业模板） | — | — | ✅ |

> 账号是**封闭式**的：系统只允许第一个注册者成为管理员（KP），之后的账号一律由 KP 发放。
> 这不是缺陷，是刻意的设计——站点面向一个固定的跑团圈子。

## 三、界面速览

### 模组档案馆

每份档案包含时代 / 地区 / 人数 / 时长 / 案件背景 / 车卡要求 / 推荐职业 / 推荐技能 / KP 备注，访客无需登录即可浏览检索。
列表卡片与详情页头图共用一套名为 **「档案封印」** 的装饰（斜纹网格、双线内框、四角角标、档案编号、蜡封印章）。

![模组详情页](docs/images/02-module-detail.png)

### 守秘人控制台

逐场记录日期、时长、在车调查员，实时汇总总场次与累计时长；另有「全模组带团盘点」按模组聚合，底部可把履历导出成证书风格长图。

![守秘人控制台](docs/images/11-kp-dashboard.png)

### 半自动车卡系统

「半自动」的意思是：**算得准的交给程序，拿主意的留给人**。

- 自动：属性掷骰与明细、年龄补正、教育增强、HP / MP / 理智 / 移动力 / 伤害加值与体格 / 闪避 / 母语、技能基础值、职业点与兴趣点预算；
- 人工：是否接受掷骰结果、点数怎么分、专攻叫什么、房规是否启用年龄补正。
- 年龄补正按规则书来：**外貌是固定减值，力量/体质/敏捷（15-19 岁为力量/体型）是「合计减 N 点、自己分配」**，
  编辑器里有专门的分配面板（还能一键平均分配）。
- 选职业时展示官方的**本职技能原文**；如果这个职业指定了专攻方向（例如牧师的「外语（拉丁语）」），
  会直接标出来并在选职业时自动预填，KP 审卡时也会逐条核对。
- 「任选 N 项其他特长」的候选池有几十项，带搜索框；社交技能只有 4 项，直接平铺。
- 教育增强（年龄成长）会留下**结算流水**：做过几次、每次骰了多少、谁结算的；**结算一次就锁定**，
  想重掷得由 KP 在列表 / 审卡中心 / 详情页点「授权重掷」，每次授权与重掷都留痕。
- KP 可以给单张卡开**传奇标记**（突破属性 99、额外调整值单独一栏），也可以**豁免年龄减益**只保留成长。
- 每张卡都能写**备注**（只记录、不打印），还能**导出成一段编码**发给别人导入，或生成**骰娘导入指令**直接发到群里。
- **角色卡搬家**：详情页 / 管理列表点「导出」拿到一段 `COC7G1:…` 编码，发给别人粘进「导入角色卡」就能变成一张新卡，
  照着改就行，不用重点一遍技能；编码带校验码，复制断了会直接提示。
- **骰娘指令**：同样在「导出」里，四种格式（DICE / 塔系 / MDice 惠惠 / shiki Exp10）与官方车卡 Excel 的
  「简化卡 骰娘导入」一致，复制就能发给 QQ 骰娘建卡；也支持 `.st` / `。st` 两种前缀。
- **KP 快捷裁定**：角色卡管理列表每张卡都有「KP 快捷」一行 —— **传奇**（突破属性 99，额外调整值单独一栏）、
  **豁免年龄**（一键，只保留教育成长）、**教育**（看成长流水、授权重掷、重置），全程不用进编辑器。


编辑器分五页（属性与职业 / 技能分配 / 战斗 / 背景故事 / 装备与经历），顶部常驻派生值看板，任何改动即时重算。
技能页默认展开**全部 54 项技能**，按官方纸质卡提供 8 组专攻下拉；「消费水平 / 现金 / 资产」由信用评级 + 时代自动推导并锁死。

![车卡编辑器：属性与职业](docs/images/07-editor-attributes.png)

![车卡编辑器：技能分配](docs/images/08-editor-skills.png)

![车卡编辑器：装备与经历](docs/images/09-editor-equipment.png)

角色卡详情页是只读视图，承载审核状态、KP 批复与模组经历：

![角色卡详情](docs/images/06-character-detail.png)

KP 侧另有「角色卡统一管理」，可按玩家、生涯状态、审核进度、模组经历筛选，支持代建、代改与批量打印：

![角色卡统一管理](docs/images/05-kp-characters.png)

### A4 打印 / 另存 PDF

用**浏览器原生打印**（`window.print()`），输出矢量文字，可选中、可搜索、放大不失真。
版面按官方纸质卡组织：属性与派生值 → 三栏技能表（一页 57 行无溢出）→ 武器表 → 背景故事十栏 → 装备资产 → 经历表。
已投点的技能自动置顶加粗，每项技能前有 ☐ 方块（对应官方卡的「大成功」标记）。
**每个技能固定占一行**（名字过长会自动缩一档字号，不会折行），上方姓名 / 玩家 / 住地等填空格同样强制单行，版面不会因为名字长就串行。

![A4 打印版面](docs/images/10-character-print.png)

### 角色卡审核

```
玩家提交 ──► pending ──┬─► KP 通过 ──► approved（批复强制清空）
                       └─► KP 驳回 ──► rejected（必须写批复）
玩家改卡：approved → none（审定失效）；rejected 保持到重新提交
```

审卡中心有四个分页：待审核队列 / 批量审卡 / 审卡规则 / 职业模板。
「打开核对」会展开 KP 专属面板：左侧完整卡面，右侧规则判定（error / warn / info 三级）与点数统计，底部「通过判定」与「驳回并批复」。

![审卡中心](docs/images/12-review-queue.png)

![审卡面板](docs/images/13-review-detail.png)

**10 条审卡规则全部可选**（数字填 0 或关掉即不检查），判定在服务端进行：
属性上下限、八项之和上限、职业点技能上限、兴趣点技能上限、禁止混点、信用评级区间、必选职业、背景故事最少栏数、职业点最低使用率、职业指定专攻方向核对，另可对自定义技能提示重点核查。

其中「禁止混点」按规则书严格拆成三条：**职业点只能投本职技能**、**同一个技能不能同时吃职业点与兴趣点**
（侦查 职业15 + 兴趣15 ✗；职业30 ✓、兴趣30 ✓）、**信用评级只能用职业点**；
兴趣点投在本职技能上时，该技能的成功率上限按「兴趣技能上限」判定。

审卡结论还会附带**成长与传奇提示**：教育增强未结算 / 重掷过几次（带最近授权人）、传奇标记与额外调整值，
以及「豁免年龄减益」状态 —— KP 在待审核队列里就能看到，不必逐张点开。

![审卡规则](docs/images/14-audit-rules.png)

KP 还可以维护**自定义职业模板**（信用评级区间、属性公式、本职技能、自定义技能名），玩家侧立即可选：

![职业模板](docs/images/15-review-occupations.png)

## 四、跑起来

前置：Node.js ≥ 20（实测 v24）、npm。

```bash
# 1) 取代码
git clone https://github.com/mrguijin/coc-modules-archive.git
cd coc-modules-archive

# 2) 安装依赖（前端 + 后端）
npm install
npm --prefix backend install

# 3) 构建前端产物
npm run build

# 4) 启动后端（默认 127.0.0.1:3000）
npm --prefix backend start

# 5) 另开一个终端：以生产产物启动站点（默认 4173，/api 自动代理到 3000）
npm run preview
```

打开 <http://localhost:4173>，点击「初始化首个账号」创建管理员（KP）——**第一个注册的账号自动成为管理员**，之后所有账号都在「账号管理」里发放。

一键脚本（Windows Git Bash / Linux / macOS）：

```bash
bash run-local.sh start     # 后端 3000 + 站点 4173
bash run-local.sh status    # 查看端口与进程
bash run-local.sh stop
bash run-local.sh logs      # 看日志
```

> 站点监听 `0.0.0.0`，同一局域网的平板/手机可以直接打开打印角色卡；后端只监听 `127.0.0.1`，由站点服务反代 `/api`，不直接对外暴露。

## 六、使用小贴士

- **账号由 KP 发放**：站点不给自助注册，第一个注册的人是 KP。
- **访客车卡存在本机浏览器**里，换设备就看不到；登录后可一键收录进档案馆。
- **打印建议用 Chrome / Edge**：A4 双页版面，直接在打印对话框里选「另存为 PDF」即可。
- **数值改不了**：HP / 理智 / 技能成功率 / 资产等派生值都在服务端重算，想改只能改输入项。
- **数据在你自己的服务器上**：全部存于 `backend/data/database.json`，每天自动留一份快照（保留 14 份）。
  备份 = 拷走 `backend/data/` 这一个目录。
- **审卡尺度可调**：9 条规则逐条开关，数字填 0 即不检查，适合不同桌的房规。
- **KP 可以代玩家建卡、改卡、批量打印**，但批复只存在审核记录里，不会印到角色卡上。

## 七、技术栈与已知限制

前端 React 19 + Vite 7 + Tailwind v4；后端 Express 5 + 单文件 JSON 存储（无数据库、无 ORM）；前后端共用同一份 COC 7e 规则引擎。

已知限制：

- **没有前端路由**：刷新会回到首页，角色卡链接无法分享；
- **单文件 JSON 存储**：适合几十人 / 几十张卡的规模，数据量再大建议迁 SQLite；
- **导入导出是文本编码**：`COC7G1:` 编码与骰娘指令都是纯文本，没有 Excel / JSON 文件互转；
- 页面标题仍是早期的 `coc模组列表`，与站点名不一致。
